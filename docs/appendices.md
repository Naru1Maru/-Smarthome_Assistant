# Приложения

## Приложение А. Терминологический словарь предметной области

В приложении А приведены основные термины, используемые в работе при описании предметной области, архитектуры системы и экспериментальной проверки.

| Термин | Определение |
| --- | --- |
| IoT | Интернет вещей; совокупность физических устройств, подключённых к сети и доступных для программного управления или мониторинга. |
| Умный дом | Программно-аппаратная среда, объединяющая бытовые устройства, датчики, исполнительные механизмы и пользовательские интерфейсы управления. |
| Устройство умного дома | Физическое устройство или виртуальная сущность, которой можно управлять через платформу умного дома: лампа, розетка, датчик, хаб, климатическое устройство. |
| Сущность | Формальное представление устройства или его функции в исполнительной среде умного дома. В Home Assistant сущности имеют идентификаторы, например `light.bedroom_lamp`. |
| Сервис | Формальный вызов действия над сущностью в Home Assistant, например включение света или установка яркости. |
| Сценарий автоматизации | Набор условий, триггеров и действий, определяющий автоматическое поведение системы без ручного запуска пользователем. |
| Триггер | Событие или условие запуска автоматизации, например наступление заданного времени. |
| Команда пользователя | Текстовая или голосовая формулировка пользователя, выражающая намерение управлять устройством или создать сценарий автоматизации. |
| Естественно-языковая команда | Команда, сформулированная бытовым языком без обязательного использования строгого синтаксиса. |
| Интент | Распознанное намерение пользователя, например включение света, изменение яркости или создание автоматизации. |
| Слот | Значимый параметр пользовательского запроса, например комната, устройство, время, яркость или цветовая температура. |
| Контекст управления | Дополнительная информация, используемая при интерпретации команды: выбранная комната, выбранное устройство, режим обработки и последние параметры взаимодействия. |
| ИИ-агент | В рамках данной работы программный компонент, который интерпретирует пользовательское намерение, формирует структурированное действие или сценарий и передаёт результат на проверку перед исполнением. |
| LLM | Большая языковая модель, применяемая для интерпретации свободных пользовательских формулировок. |
| Rule-based модуль | Модуль интерпретации команд на основе словарей, шаблонов, нормализации текста и детерминированных правил. |
| Гибридная интерпретация | Подход, при котором правила используются для типовых команд, а LLM применяется для сложных, неоднозначных или свободных формулировок. |
| Сервер-шлюз | Промежуточный серверный компонент между мобильным приложением, модулем интерпретации и исполнительной средой. |
| Валидация | Проверка структурированного результата интерпретации перед исполнением: наличие цели, допустимость действия, корректность параметров и соответствие возможностям устройства. |
| Dry-run | Режим безопасной проверки, при котором команда проходит интерпретацию и валидацию, но не отправляется на фактическое исполнение. |
| Предварительное представление сценария | Результат построения сценария до его сохранения в Home Assistant; используется для проверки и подтверждения пользователем. |
| Локальная обработка | Выполнение интерпретации и обработки команд в локальной инфраструктуре без обязательной передачи пользовательских команд во внешние облачные сервисы. |

## Приложение В. Исходные данные для экспериментов

В приложении В приведён состав исходных данных, использованных для экспериментальной проверки качества интерпретации команд, сценарного режима и сопоставления с внешним аналогом. Полные наборы данных хранятся в электронном виде в каталоге `smarthome_core/data`.

Таблица В.1 — Наборы исходных данных для экспериментальной проверки.

| Файл | Назначение | Объём | Использование в работе |
| --- | --- | ---: | --- |
| `light_gold_eval100_ru_v1.jsonl` | Основной размеченный набор команд управления освещением | 100 фраз | Оценка качества интерпретации команд в LLM-режиме |
| `light_gold_eval100_ru_v1_direct.jsonl` | Подмножество прямых команд | 50 фраз | Анализ качества на стандартных формулировках |
| `light_gold_eval100_ru_v1_creative.jsonl` | Подмножество свободных и творческих команд | 50 фраз | Анализ качества на нестандартных формулировках |
| `scenario_eval24_ru_v1.jsonl` | Набор пользовательских формулировок сценариев автоматизации | 24 фразы | Оценка сценарного режима |
| `light_yandex_compare_bedroom_creative50_ru_v1.jsonl` | Набор творческих команд управления светом в спальне | 50 фраз | Сравнение разработанной системы с Алисой |
| `light_yandex_compare_bedroom_creative50_ru_v1_results_template.csv` | Шаблон ручной фиксации результатов Алисы | 50 строк | Заполнение результатов закрытой промышленной системы вручную |

Формат JSONL использовался для хранения тестовых фраз и эталонной разметки. Каждая строка файла соответствует одной тестовой записи. В зависимости от набора запись может включать текст команды, ожидаемое действие, целевую комнату, параметры действия, ожидаемый статус обработки и служебные признаки для последующего анализа.

Пример обобщённой структуры записи:

```json
{
  "id": "example_001",
  "text": "Сделай в спальне свет поуютнее",
  "area": "Спальня",
  "expected_behavior": "приглушённый тёплый свет",
  "split": "creative"
}
```

Приведённый пример отражает общий принцип разметки и не заменяет полные исходные файлы, использованные при расчёте метрик.
